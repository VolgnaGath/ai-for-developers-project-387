# Календарь целиком в таймзоне конфига

Весь календарь фронтенда живёт в `PublicConfig.timezone`: сетка месяца, «сегодня», границы дней и вычисление `from`/`to` для `listSlots`. Таймзона браузера гостя в v1 нигде не участвует; рядом с календарём показывается подпись «Время: {timezone}».

Решили так, потому что контракт трактует `from`/`to` и рабочие часы именно в таймзоне конфига, а слоты отдаёт как `utcDateTime`. Если строить сетку в таймзоне браузера, одни и те же слоты лягут на разные календарные дни относительно того, что понимает сервер, и день в UI перестанет совпадать с `from`/`to`, которые сервер режет в таймзоне конфига.

## Considered Options

- **Таймзона браузера гостя**: отвергнута — ломает соответствие сетки `from`/`to` контракта и усложняет date-слой без выгоды для контракта.
- **Гибрид (сетка в конфиге, подписи гостю в его таймзоне)**: отложена — двойное отображение времени вводит второй источник истины для границ дня; в v1 не требуется.
